## 3. 阻塞说明与最小复现

### 3.1 环境事实

- MySQL Windows 服务 `MySQL80` 正在运行。
- 工作区存在 `.env.example`，但不存在 `.env`。
- `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`、`TEST_DB_NAME` 均未在当前进程环境中设置。
- 连接 URL 因此解析为用户名 `None`，不是有效的项目数据库账号。

### 3.2 最小复现

```powershell
$env:DB_NAME='smart_beam_twin_test'
.\.venv\Scripts\python.exe -m alembic current
```

结果：

```text
OperationalError 1045: Access denied for user 'None'@'localhost' (using password: NO)
```

`alembic check` 和依赖数据库的结构测试产生相同认证错误。没有执行成功的数据库连接、迁移或写入。

### 3.3 影响

以下交接必测项无法形成有效结论：

1. V9 真实表结构、字段精度、外键、检查约束、唯一约束和索引反射；
2. 八类异常在 MySQL 中的创建、项目隔离和梁关联；
3. 编码/外部幂等、首次并发创建及冲突恢复；
4. 状态机、相同动作幂等和并发行锁；
5. 创建及状态变化的事务回滚和副作用；
6. 筛选、关键词、含总数/无总数分页和稳定排序；
7. 测试库及开发库升级、降级、重新升级和 `alembic check`；
8. V1～V8 完整数据库回归；
9. 测试数据残留检查。

该阻塞属于环境配置缺失，当前没有证据将其认定为 V9 产品代码缺陷；但它直接阻止版本验收和冻结。

数据库恢复后必须至少补测：

1. 相同编码、相同外部键、不同内容及“双键分别指向不同记录”的分裂冲突；

3. 并发开始处理、解决和关闭，验证行锁、首次快照不覆盖及无数据库异常泄漏；
4. `OPEN -> IN_PROGRESS -> RESOLVED -> CLOSED`、`OPEN -> RESOLVED -> CLOSED` 及全部非法路径；
5. 项目停用后的相同建档重试、拒绝新建和允许既有事项收尾；
6. 用户显示名变更后，上报人和各状态节点名称快照仍保持历史值；
7. 创建及各状态动作 flush 后 DTO 转换失败时完整回滚；
8. 梁状态、V5 生命周期事件和 V3 操作审计无自动副作用；
9. 空多值筛选匹配零条、关键词通配符转义、同值稳定排序及无总数分页；
10. 真实 MySQL 检查约束、`DATETIME(6)`、6 个外键和 4 组组合索引；
