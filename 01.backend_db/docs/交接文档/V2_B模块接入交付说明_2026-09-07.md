## 2. B 的接入边界

B 通过同步 Python Service 调用 A，不直接访问数据库，也不通过 A 提供的 HTTP 接口调用。A 当前不提供 FastAPI 路由。

B 只允许依赖：

```python
from backend_db.interfaces import create_database_services
from backend_db.schemas import BeamCreate, BeamFilter, PageRequest
from backend_db.exceptions import BackendDBError
```

B 不得导入或使用：

- `backend_db.models`；
- `backend_db.crud`；
- `backend_db.database`；
- `backend_db.services` 中的具体实现类；
- SQLAlchemy Session、ORM 对象、查询对象、表对象或原生 SQL。

A 返回的对象均为 Pydantic DTO。转换为 HTTP JSON 响应时建议使用：

```python
payload = result.model_dump(mode="json")
```

## 3. 安装和初始化

在 B 自己的 Python 3.11+ 虚拟环境中，从仓库根目录执行：

```powershell
python -m pip install -e .\01.backend_db
```

B 的运行环境需要配置：

```text
DB_HOST
DB_PORT
DB_USER
DB_PASSWORD
DB_NAME
```

应用启动时创建一次服务集合并复用：

```python
from backend_db.interfaces import create_database_services

database_services = create_database_services()
```

每次 Service 方法调用都会自行创建和关闭数据库 Session。B 不提交、不回滚，也不保存 Session。

## 4. B 可调用的公开服务

| 服务属性 | 已提供能力 |
| --- | --- |
| `database_services.projects` | 项目创建、读取、分页查询、更新和启停 |
| `database_services.processes` | 通用/项目级工序基础资料创建、读取、分页、更新和启停 |
| `database_services.users` | 用户资料、认证记录、密码散列存储、更新和启停 |
| `database_services.access_control` | 角色、权限、系统角色、项目成员、项目角色和有效权限 |
| `database_services.beam_types` | 梁型创建、读取、筛选、更新和启停 |
| `database_services.yard_areas` | 梁场区域创建、读取、筛选、区域树、更新和启停 |
| `database_services.beam_positions` | 梁位创建、读取、筛选、占用查询、更新和启停 |
| `database_services.beams` | 梁创建、读取、筛选、更新、状态修改和梁位操作 |

各方法的精确参数和返回 DTO 以 `backend_db.interfaces` 中的公开 Protocol 为准。完整清单见 `docs/A-B接口接入说明.md`。

## 5. 项目作用域规则

梁型、区域、梁位、梁和工序都按项目隔离。B 必须从当前请求的项目路由、登录上下文或明确业务参数中取得 `project_code`，不能自行猜测项目归属。

- `project_code=None`：只访问 V1 全局数据，即 `project_id IS NULL`；
- 传入 `project_code="P001"`：只访问 `P001` 的项目数据；
- 列表查询同时传入 `include_global=True`：返回指定项目数据和 V1 全局数据；
- 按 ID 或编码读取、更新、启停、修改状态和操作梁位时，必须传入匹配的 `project_code`；
- 梁、梁型、区域和梁位之间只能建立同一项目内的关联；
- 新建项目级数据时，应在 Create DTO 中提供 `project_code`；省略时创建的是兼容 V1 的全局数据。

示例：

```python
from backend_db.schemas import BeamFilter, BeamStatus, PageRequest

page = database_services.beams.list(
    filters=BeamFilter(
        project_code="P001",
        statuses=[BeamStatus.STORED],
        is_positioned=True,
    ),
    page_request=PageRequest(page=1, page_size=20),
)
```

## 6. 推荐的基础资料创建顺序

项目级梁场数据存在关联依赖，建议 B 按以下顺序调用：

1. `projects.create` 创建项目；
2. `beam_types.create` 创建项目梁型；
3. `yard_areas.create` 创建项目区域；
4. `beam_positions.create` 创建属于该区域的梁位；
5. `beams.create` 创建使用该梁型的梁；
6. 使用 `beams.assign_position`、`move_beam` 和 `release_position` 管理当前梁位；
7. 使用 `beams.change_status` 修改梁状态。

示例：

```python
from backend_db.schemas import (
    BeamCreate,
    BeamPositionCommand,
    BeamPositionCreate,
    BeamStatus,
    BeamStatusChange,
    BeamTypeCreate,
    ProjectCreate,
    YardAreaCreate,
)

project_code = "P001"

database_services.projects.create(
    ProjectCreate(project_code=project_code, project_name="示例项目")
)
database_services.beam_types.create(
    BeamTypeCreate(
        type_code="T40",
        type_name="40米箱梁",
        project_code=project_code,
    )
)
database_services.yard_areas.create(
    YardAreaCreate(
        area_code="YARD-A",
        area_name="A存梁区",
        area_type="STORAGE",
        project_code=project_code,
    )
)
database_services.beam_positions.create(
    BeamPositionCreate(
        position_code="A-001",
        position_name="A区001梁位",
        area_code="YARD-A",
        project_code=project_code,
    )
)
database_services.beams.create(
    BeamCreate(
        beam_code="BEAM-001",
        beam_type_code="T40",
        project_code=project_code,
    )
)
database_services.beams.assign_position(
    "BEAM-001",
    BeamPositionCommand(position_code="A-001"),
    project_code=project_code,
)
database_services.beams.change_status(
    "BEAM-001",
    BeamStatusChange(status=BeamStatus.STORED),
    project_code=project_code,
)
```

`assign_position` 只用于尚未分配梁位的梁；已有梁位时调用 `move_beam`。重复移动到当前梁位和重复释放空梁位按幂等成功处理。

## 7. 登录与权限接入

A 只存储 B 提供的密码散列。密码明文校验、散列算法、JWT、Cookie、Session、登录态、HTTP 鉴权和页面/岗位权限映射均由 B 实现。

推荐登录流程：

1. B 接收用户名和密码；
2. 调用 `users.get_auth_record(username)`；
3. B 检查用户是否启用，并使用自己的密码算法校验 `password_hash`；
4. B 生成 JWT 或 Session；
5. 访问项目接口时，调用 `access_control.get_effective_permissions(username, project_code=...)`；
6. B 根据返回的稳定权限编码决定是否允许访问路由。

```python
auth_record = database_services.users.get_auth_record(username)

# B 在此校验明文密码与 auth_record.password_hash。

permission_set = database_services.access_control.get_effective_permissions(
    username,
    project_code="P001",
)
```

`UserAuthRecord` 只用于登录校验，禁止直接作为 HTTP 响应返回。普通用户 DTO 不包含密码散列。

角色范围分为 `SYSTEM` 和 `PROJECT`。系统角色只能使用 `assign_system_role` 分配；项目角色只能先通过 `add_project_member` 建立成员关系，再使用 `assign_project_role` 分配。授权和撤权均为幂等操作。

## 8. 分页和异步框架

列表方法统一接收 `PageRequest`，默认页码为 1、每页 20 条，每页最多 100 条。返回 `PageResult`，包含 `items`、`total`、`has_next` 和 `has_previous`。

排序字段必须使用对应的 `*SortField` 枚举，不能把 HTTP 请求中的任意字段名直接传给数据库层。

A 提供同步调用。如果 B 使用 FastAPI 异步路由，应由 B 将调用安排在线程池中，避免阻塞事件循环。不要在异步路由中直接持有或跨线程传递 A 的数据库 Session。

## 9. 异常映射建议

B 应捕获 `BackendDBError` 及其子类，并依据异常类型或稳定的 `code` 转换 HTTP 响应，不要依赖中文异常文本。

| A 异常类别 | 建议 HTTP 语义 |
| --- | --- |
| `ResourceNotFoundError` | `404 Not Found` |
| `ResourceConflictError` | `409 Conflict` |
| `InvalidDataError` | `400 Bad Request` 或 `422 Unprocessable Entity` |
| Pydantic `ValidationError` | `422 Unprocessable Entity` |
| `DatabaseUnavailableError` | `503 Service Unavailable` |
| 其他 `BackendDBError` | B 的统一数据库模块错误响应 |

位置占用、唯一编码冲突、无效区域层级、停用资源引用和无效梁状态均已由 A 转换为公开异常。

## 10. 事务注意事项

- 每个 Service 方法调用是一个独立事务；
- 写方法成功后由 A 提交，失败时由 A 回滚；
- B 不应假设连续多个 Service 调用属于同一个原子事务；
- 梁位分配、移动、释放和占用检查在单次 A 调用内完成并发保护；
- 如果 B 需要跨多个操作的原子业务，应先提出新的 A 层用例接口，不能绕过公开接口直接控制 Session。

## 11. 当前未提供的能力

V2 当前不提供：

- 梁、项目、用户、角色、权限、工序等核心数据的物理删除接口；
- 工序流转、状态机或生产任务编排；
- 梁状态变更历史；
- 工单、质量记录和运输记录；
- 二维码/RFID 独立身份模型；
- 设备、告警和运行期审计事件；
- 游标增量同步；
- FastAPI、Redis、MQTT、WebSocket 和 UE5 接口实现。

`processes` 当前只管理工序基础资料；`BeamStatus` 当前只校验稳定状态编码，不校验业务状态流转顺序。
