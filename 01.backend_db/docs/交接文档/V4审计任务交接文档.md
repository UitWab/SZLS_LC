# 数据库模块 V4 审计任务交接文档

## 1. 审计目标

对 A 模块 V4 梁位工单进行独立只读审查，重点发现数据完整性、并发、状态流转、迁移、项目隔离、接口耦合、查询性能、测试覆盖和 A/B 职责越界问题。

## 2. 审计边界

审计任务只读，不修改代码、数据库或文档，不提交、不推送。V4 只应包含 A 的模型、DTO、CRUD、Service、接口契约、迁移、测试和文档，不应出现 B 的 HTTP、登录鉴权、页面、审批、调度、消息或设备控制实现。

## 3. 重点检查

1. Model、Schema、CRUD、Service、Interface 是否保持单向分层，对外是否只返回 DTO。
2. 类型与状态是否以可扩展字符串保存，是否避免通用工作流过度设计。
3. 工单业务字段是否在创建后不可任意修改，是否不存在删除入口。
4. 同一根梁未结束工单的并发创建是否由梁行锁串行化。
5. 完成工单是否锁定梁、核对原梁位、检查目标占用，并与梁位变更处于同一事务。
6. 所有读取和状态动作是否按 `project_code` 隔离，跨项目是否统一表现为不存在。
7. 迁移是否可逆，模型和数据库是否无差异，外键删除策略和索引是否合理。
8. 列表查询是否稳定分页，筛选字段和排序字段是否为白名单。
9. `IntegrityError` 和数据库异常映射是否会掩盖重要业务错误。
10. 新测试是否覆盖成功、冲突、回滚、项目隔离和接口边界，并确保 V1 至 V3 无回归。

## 4. 报告要求

问题按 P0 至 P3 分级，给出准确文件位置、证据、影响和最小修改建议。若没有问题，明确已审范围和仍需通过真实并发、部署环境或 B 联调验证的外部限制。
