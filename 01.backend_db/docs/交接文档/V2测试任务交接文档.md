## 六 建议测试顺序

### 1 环境与依赖

在 A 模块目录执行：

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m compileall -q backend_db
```

记录 Python 版本、依赖检查结果和编译结果。

### 2 全量自动测试

显式锁定测试库后执行：

```powershell
$env:DB_NAME = 'smart_beam_twin_test'
.\.venv\Scripts\pytest.exe -q
```

当前开发完成时的参考结果是 `112 passed`。参考结果不是放行依据；必须记录本次实际通过数、失败数、耗时和失败堆栈。

### 3 迁移一致性

在测试库执行：

```powershell
$env:DB_NAME = 'smart_beam_twin_test'
.\.venv\Scripts\alembic.exe current
.\.venv\Scripts\alembic.exe check
```

预期当前版本为 `e5c1a7b3d902 (head)`，且显示没有待生成的迁移操作。

### 4 最新迁移往返

只在测试库验证最新工序迁移：

```powershell
$env:DB_NAME = 'smart_beam_twin_test'
.\.venv\Scripts\alembic.exe downgrade d2a8f41c6e90
.\.venv\Scripts\alembic.exe upgrade head
.\.venv\Scripts\alembic.exe current
.\.venv\Scripts\alembic.exe check
```

降级后应不存在 `process_definition`，再次升级后应恢复该表、外键、唯一约束和索引。任何命令失败时立即停止，不继续修改迁移版本号掩盖错误。

### 5 开发库只读检查

清除当前终端临时设置的 `DB_NAME` 后，执行开发库只读检查：

```powershell
Remove-Item Env:DB_NAME -ErrorAction SilentlyContinue
.\.venv\Scripts\alembic.exe current
.\.venv\Scripts\alembic.exe check
```

不得对开发库执行 downgrade。

### 6 功能测试矩阵

逐项确认自动测试是否覆盖并通过：

| 模块 | 必测行为 |
| --- | --- |
| 项目 | 新建、读取、更新、分页筛选、排序、启停、编码唯一 |
| 工序 | 通用工序、项目工序、项目加通用查询、更新归属、排序、启停、编码唯一 |
| 用户 | 普通 DTO 不含密码散列、认证记录隔离、更新散列、启停、分页筛选 |
| 角色权限 | 目录增改查、分页筛选、启停、授权撤权幂等 |
| 系统角色 | 只接受 `SYSTEM` 角色、分配撤销幂等、可查询 |
| 项目成员 | 加入、分页、启停、重复加入幂等 |
| 项目角色 | 只接受 `PROJECT` 角色、分配撤销幂等 |
| 有效权限 | 系统与项目权限合并去重；停用用户、角色、权限或成员后正确排除 |
| V1 回归 | 梁型、区域、梁位、梁 CRUD 和梁位并发占用规则不退化 |
| 接口边界 | 工厂只返回公开 Service；返回 DTO；无物理删除接口；B 无需 ORM 或 Session |

如果覆盖不足，只报告缺少的测试场景，不直接补写测试。

### 7 包构建

在临时输出目录构建：

```powershell
.\.venv\Scripts\python.exe -m pip wheel . --no-deps --no-build-isolation --wheel-dir .v2_test_wheel
```

预期生成 `smart_beam_twin_backend_db-2.0.0-py3-none-any.whl`。记录名称和大小，随后仅清理本次创建的 `.v2_test_wheel` 临时目录。

## 七 失败处理原则

- 保留原始错误输出和复现命令。
- 区分代码缺陷、测试缺陷、环境缺陷和数据库状态缺陷。
- 数据库迁移失败时记录失败前后的 Alembic 版本及相关表状态。
- 不通过修改测试、跳过测试、手工改版本号或降低断言来获得通过结果。
- 不修复问题；将修复建议单独列出，等待主开发任务确认。

## 八 测试报告格式

测试完成后按以下结构回复：

1. 结论：通过、有限通过或不通过。
2. 环境：Python、MySQL、分支、工作区状态、迁移版本。
3. 执行结果：逐条列出命令、通过数、失败数和关键输出。
4. 功能矩阵：每项标记通过、失败或未覆盖。
5. 缺陷：严重级别、复现步骤、期望结果、实际结果、影响范围。
6. 数据库状态：测试库和开发库最终版本，是否恢复到预期状态。
7. 工作区状态：测试前后差异，是否存在测试生成残留。
8. 是否建议冻结 V2。

不得只回复“测试通过”。所有结论必须附带可复核证据。
