# 数据库模块 V4 B模块接入交付说明

## 1. 新增能力

V4 在 V3 全部公开能力基础上新增 `database_services.position_work_orders`，用于梁场内部入位、移位和出位工单。A 负责数据校验、项目隔离、并发保护、状态流转和事务；B 负责接口、权限、触发时机和交互流程。

## 2. 公开方法

- `create(BeamPositionWorkOrderCreate) -> BeamPositionWorkOrderRead`
- `get(work_order_id, project_code=...) -> BeamPositionWorkOrderRead`
- `get_by_code(work_order_code, project_code=...) -> BeamPositionWorkOrderRead`
- `list(BeamPositionWorkOrderFilter, PageRequest, sort_by, sort_order) -> PageResult[BeamPositionWorkOrderSummary]`
- `start(work_order_code, project_code=...) -> BeamPositionWorkOrderRead`
- `complete(work_order_code, project_code=...) -> BeamPositionWorkOrderRead`
- `cancel(work_order_code, project_code=...) -> BeamPositionWorkOrderRead`

类型：`PLACE`、`MOVE`、`RELEASE`。状态：`PENDING`、`IN_PROGRESS`、`COMPLETED`、`CANCELED`。

## 3. 关键语义

创建工单不会预占目标梁位。完成时 A 重新锁定梁、核对原梁位并检查目标占用；实际梁位变更与工单完成在一个事务中提交或回滚。同一根梁最多存在一个未结束工单。

工单不提供任意更新和删除。B 不得通过 ORM、CRUD 或 Session 修改工单，也不应在调用工单 `complete` 后再次调用 `beams` 梁位操作。

## 4. B 的责任与边界

B 从当前登录和项目上下文取得 `project_code`，完成权限判断后调用 A。B 决定工单创建、开始、完成、取消的触发时机，并负责 HTTP/消息映射、操作提示和审计记录。

V4 不包含页面、FastAPI、JWT、审批、派工、调度算法、设备控制、MQTT、WebSocket 或 UE5 同步实现。
