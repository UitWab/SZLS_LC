# V9 异常事项记录设计草案

- 文档状态：已按确认口径进入开发，待真实数据库验证、独立测试和审计
- 依赖基线：`backend-db-v8.0.0`
- 预计包版本：`9.0.0`
- 范围：A 数据库模块的统一异常事项存储、查询和受控状态变化

## 1. 需求结论

业主需求要求统一查看进度、生产、质量、存梁、物流、设备、安全和巡检等未关闭异常，并按类型、等级和处理状态展示。V9 因此不再限定为设备告警，而建设一个边界明确的异常事项领域。

V9 保存已经由 B、外部系统或设备判定成立的异常事项。A 不计算超期、不判断测点阈值、不连接设备，也不发送通知。

## 2. 负责范围

V9 实现：

- `abnormal_issue` ORM 模型和单一向前迁移；
- Pydantic DTO、CRUD、Service 和公开 Python Protocol；
- 项目必填、可空梁关联和可空设备编码；
- 异常分类、等级、当前状态和处理节点快照；
- 外部幂等、并发创建恢复和状态行锁；
- 页码分页、条件筛选、稳定排序和公共异常；
- 自动测试、数据字典、A-B 接入说明及测试审计交接材料。

V9 不实现：

- HTTP、登录鉴权、页面、岗位权限和消息通知；
- PLC、MQTT、传感器、设备网关或原始报文接入；
- 时序测点、阈值计算、自动异常识别和设备控制；
- 设备档案、异常派工、通用工单或通用工作流；
- 自动修改梁状态或自动写入 V3 操作审计日志；
- 任意 JSON 载荷、文件和图片存储。

## 3. 记录含义

每条 `abnormal_issue` 表示一个已经成立、需要展示或处理的异常事项。相同问题再次发生时使用新的 `issue_code` 和外部记录标识，不重新打开已经关闭的事项。

异常事项必须属于一个项目。只有异常明确关联某片梁时才填写 `beam_id`；设备来源可填写稳定的 `device_code` 字符串，第一版不建立设备外键。

## 4. 分类和等级

分类使用稳定字符串代码和 Python `StrEnum`，不使用 MySQL ENUM：

- `PROGRESS`：进度异常；
- `PRODUCTION`：生产异常；
- `QUALITY`：质量异常；
- `STORAGE`：存梁异常；
- `LOGISTICS`：转运、运输或到场异常；
- `EQUIPMENT`：设备异常、离线或报警事项；
- `SAFETY`：高风险作业或现场安全异常；
- `INSPECTION`：巡检发现的问题。

等级为 `INFO`、`WARNING`、`CRITICAL`。B 负责按照业务规则选择分类、具体 `issue_type_code` 和等级，A 只验证代码是否属于稳定契约。

## 5. 状态规则

状态为：

- `OPEN`：异常已记录，尚未开始处理；
- `IN_PROGRESS`：已经开始处理；
- `RESOLVED`：异常已经解决，等待复核关闭；
- `CLOSED`：复核完成并关闭。

允许的变化：

- `OPEN -> IN_PROGRESS`；
- `OPEN -> RESOLVED`；
- `IN_PROGRESS -> RESOLVED`；
- `RESOLVED -> CLOSED`。

不允许任意状态赋值、关闭后重开或未解决直接关闭。相同动作使用相同内容重试时返回当前记录；若处理人、解决摘要或关闭备注不同，则返回稳定冲突异常，不覆盖既有事实。

第一版在主表保存各阶段时间和人员快照，不增加处置流水子表。若以后明确要求多次转派、处理意见、附件或完整复核历史，应新增独立历史表，不把自由 JSON 塞入主表。

## 6. 幂等和并发

- `issue_code` 全表唯一；
- 提供 `external_record_id` 时，`source + external_record_id` 唯一；
- 相同幂等键且业务内容完全一致时返回既有记录；
- 相同幂等键但内容不同返回 `ResourceConflictError`；
- 并发首次写入由数据库唯一约束兜底，Service 在新事务中恢复既有记录；
- 状态动作使用 `SELECT ... FOR UPDATE` 锁定单条异常事项，避免并发覆盖；
- 项目停用后不允许新建异常，但既有请求重试和既有异常收尾仍可执行。

## 7. 项目和引用规则

- `project_code` 创建、读取、列表和状态动作均必填；
- 数据库 `project_id` 非空，不创建全局异常；
- 提供 `beam_code` 时，梁必须存在且属于同一项目；
- 跨项目读取和状态动作统一表现为异常事项不存在；
- 操作用户只验证存在性，不在 A 判断其项目权限；权限判断属于 B；
- `device_code` 只是外部稳定标识，不证明设备档案存在。

## 8. 查询和索引

列表支持项目、异常编码、梁、设备、多个分类、多个类型、多个等级、多个状态、多个来源、业务时间、外部标识和关键词筛选。

默认按 `occurred_at DESC, id DESC` 排序；非 ID 排序追加同方向 `id`，保证相同值下分页稳定。第一版继续使用 `PageRequest` 和 `PageResult`，暂不增加游标接口。

索引只覆盖明确查询路径：

- `(project_id, occurred_at, id)`；
- `(project_id, status, occurred_at, id)`；
- `(project_id, category_code, status, occurred_at, id)`；
- `(beam_id, occurred_at, id)`；
- `(project_id, device_code, occurred_at, id)`。

## 9. 公开接口

组合入口新增 `create_database_services().abnormal_issues`：

- `record(data)`；
- `get(issue_code, project_code=...)`；
- `list(filters, page_request, sort_by, sort_order)`；
- `start_processing(issue_code, data, project_code=...)`；
- `resolve(issue_code, data, project_code=...)`；
- `close(issue_code, data, project_code=...)`。

不提供 `update`、`delete`、`reopen`、`detect`、`notify`、`dispatch` 或设备控制接口。

## 10. 兼容和扩展

V9 不修改 V1 至 V8 表和既有方法。后续新增异常分类、等级或来源时优先追加稳定代码；废弃值保留历史读取。设备档案、自动告警、处置历史和异常增量推送均需独立需求和向前迁移。
