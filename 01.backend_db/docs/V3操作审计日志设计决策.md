# 智能建梁数字孪生平台数据库 V3 操作审计日志设计决策

## 1. 目标与范围

V3 只新增操作审计日志的底层存储与查询能力。B 决定何时记录审计、动作代码、结果代码及摘要内容；A 负责引用资源校验、事务、持久化、筛选、分页和 DTO 边界。

V3 不开发 FastAPI、登录流程、JWT、鉴权、消息广播、设备、告警、工单、状态历史、增量同步或 UE5 功能，也不改造既有 Service 自动写审计。

## 2. 核心决策

1. 表名为 `operation_audit_log`。
2. 记录只追加，不提供更新、启停或删除接口。
3. `project_id` 可空，支持系统级操作。
4. `actor_user_id` 可空，支持未登录失败和系统操作。
5. `actor_name` 保存操作人显示名称或标识快照；提供有效用户ID但未提供名称时，A 使用当前用户显示名称。
6. `action_code`、`resource_type` 和 `result_code` 由 B 定义，A 只校验非空和长度，不固化业务枚举。
7. `request_id` 只用于追踪，不设置唯一约束，不提供幂等语义。
8. `occurred_at` 由 B 提供，`created_at` 由 A 按 UTC 写入。
9. 不增加通用 JSON 详情字段，避免未受控结构及敏感数据进入审计表。
10. B 不得写入密码、密码散列、JWT、Session令牌、Cookie、数据库连接串、完整请求头或完整请求体。

## 3. 公开接口

组合工厂新增 `database_services.audit_logs`：

- `record(data)`：追加记录；
- `get(audit_log_id, scope, project_code)`：在显式范围内按ID读取；
- `list(filters, page_request, sort_by, sort_order)`：条件筛选、页码分页和稳定排序。

所有接口返回 Pydantic DTO，不暴露 ORM、CRUD 或数据库 Session。

读取范围使用 `OperationAuditLogScope` 明确表达：`SYSTEM` 只读取系统级日志，`PROJECT` 必须同时提供 `project_code`，`ALL` 显式读取全部日志。查询不提供隐式全项目默认值。`ALL` 只是数据库查询能力，B 必须在调用前完成系统级权限判断。

## 4. 事务和异常

每次 `record` 是独立事务，成功提交、失败回滚。项目编码存在时必须解析到真实项目；操作用户ID存在时必须解析到真实用户。不存在时分别返回 `ProjectNotFoundError` 和 `UserNotFoundError`。指定范围内的审计日志不存在时返回 `OperationAuditLogNotFoundError`，不暴露其他项目是否存在同一日志ID。

## 5. 后续扩展边界

设备档案、时序测点、告警、梁位工单、梁生命周期历史和数字孪生增量同步继续等待业务口径确认，不因 V3 审计模块自动进入开发范围。
