- **版本：** V5.0 开发完成版（待冻结）
- **数据库：** MySQL 8.0.x
- **ORM 与迁移：** SQLAlchemy 2.x 与 Alembic
- **基线迁移：** `a4d7e9f2c105`
- **V5 迁移版本：** `c8f2d4e6a013`
- **新增范围：** `beam_lifecycle_event`、内部事件流锁表和增量查询索引
- **业务时间：** 无时区标记的 UTC `DATETIME(6)`

## 当前约定

- `beam_lifecycle_event` 是梁生命周期事实记录，只追加，不提供更新、删除、启停或归档。
- V5 不回填历史，只记录上线后由 A 模块成功提交的梁变化。
- 事件与对应梁变化在同一事务内提交或回滚。
- 操作人和请求审计继续保存在 `operation_audit_log`，不在生命周期事件中重复建模。
- 项目、梁、梁位和工单外键均使用 `RESTRICT`。
- `project_id` 跟随梁项目；为兼容 V1 全局梁允许为空。
- `occurred_at` 和 `created_at` 由 A 模块使用 UTC 时间写入，不接受 B 自定义事件时间。
- 同一项目或全局范围内的事件写入通过内部事务锁串行化，使事件 ID 顺序与提交顺序一致；不同项目互不阻塞。

## 事件类型代码

| 代码 | 中文名称 | 字段规则 |
|---|---|---|
| `BEAM_CREATED` | 梁已创建 | `status_after` 必填；其他变化字段为空。 |
| `STATUS_CHANGED` | 梁状态已变化 | `status_before`、`status_after` 必填且不同。 |
| `POSITION_ASSIGNED` | 梁已入位 | `source_position_id` 为空，`target_position_id` 必填。 |
| `POSITION_MOVED` | 梁已移位 | 两个梁位字段必填且不同。 |
| `POSITION_RELEASED` | 梁已出位 | `source_position_id` 必填，`target_position_id` 为空。 |

## 查询约定

- 管理查询支持项目、梁、多个事件类型和发生时间范围筛选，并使用页码分页。
- 增量查询按事件 `id` 升序执行，使用排他游标和 `limit`；`occurred_at` 只表达业务发生时间。
- 对外 DTO 返回 `project_code`、`beam_code`、梁位编码和工单编码，不暴露 ORM 对象。
- 不同项目或不同筛选条件分别保存游标。客户端按事件 ID 幂等处理重试数据。
- 当前游标为版本 2，V5 修复前生成的旧版游标需在部署时重置。
