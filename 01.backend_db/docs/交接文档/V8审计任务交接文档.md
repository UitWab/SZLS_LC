# V8 运输交接记录审计任务交接文档

## 1. 审计目标

对 V8 未提交工作区进行独立、只读审查，评估数据完整性、项目隔离、幂等并发、作废、迁移、查询性能、异常契约、测试覆盖和 A/B 边界。审计任务不修改代码、数据库或文档，不提交、打标签或推送。

## 2. 基线和重点文件

- 依赖基线：`backend-db-v7.0.0`；
- 目标包版本：`8.0.0`；
- 目标迁移：`f8c2d4e6a709`；
- 设计：`docs/V8运输交接记录设计草案.md`；
- 实现：`models/schemas/crud/services/beam_transport_handover.py`；
- 契约：`interfaces/contracts.py`、`interfaces/factory.py`、`docs/A-B接口接入说明.md`；
- 测试：`tests/test_beam_transport_handover.py`、`test_schema.py`、`test_interfaces.py`。

## 3. 必审问题

1. 三种类型的地点必填规则是否与设计一致，是否无意增加未确认约束；
2. `project_id` 是否始终从梁派生，读写是否防止跨项目泄漏；
3. 幂等是否比较全部业务字段，并发唯一冲突恢复是否在新事务执行；
4. 停用项目的完全相同重试是否保持幂等，新记录是否被拒绝；
5. `void` 是否行锁定、幂等且不覆盖首次作废信息；
6. CRUD 是否禁止任意字段修改，Service 是否是唯一公开写入边界；
7. 页码分页是否稳定，筛选/排序是否白名单，索引是否与查询路径相符；
8. 记录是否隐式修改梁状态、V5 事件、V3 日志或开发 B 的调度/鉴权功能；
9. 迁移是否可独立回退，模型和迁移是否一致；
10. 异常是否稳定且不泄漏 ORM、Session、SQL 或索引名。

## 4. 输出格式

问题按 P0 至 P3 分级，每项给出文件与行号、可复现证据、影响、最小修复方向和建议验收测试。如无问题，明确说明已审范围和仍存在的外部限制。
