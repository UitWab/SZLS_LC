# 数据库模块 V3 B模块接入交付说明

## 1. 新增能力

V3 在V2全部公开能力基础上新增 `database_services.audit_logs`。B可以显式追加并查询操作审计日志。该能力不自动拦截HTTP请求，也不自动审计登录、权限或消息处理。

## 2. 方法

- `record(OperationAuditLogCreate) -> OperationAuditLogRead`
- `get(audit_log_id, *, scope, project_code=None) -> OperationAuditLogRead`
- `list(OperationAuditLogFilter, PageRequest, sort_by, sort_order) -> PageResult[OperationAuditLogSummary]`

默认按 `occurred_at DESC, id DESC` 排序。`request_id` 只用于追踪，不唯一，不承担幂等。

查询必须显式指定 `OperationAuditLogScope`：`SYSTEM` 只读取系统级日志；`PROJECT` 必须提供 `project_code`，只读取该项目；`ALL` 读取系统级和全部项目日志。`SYSTEM`、`ALL` 不允许同时提供 `project_code`。

## 3. B的责任

B负责定义动作、结果和来源代码，并决定记录时机。B必须在构造DTO前排除密码、密码散列、JWT、Session令牌、Cookie、数据库连接串、完整请求头和完整请求体。

项目级记录传 `project_code`；系统级记录可不传。已登录操作可传 `actor_user_id`；未登录失败或系统操作可只传 `actor_name`。A不根据审计字段执行权限判断。

B 在项目接口中应使用 `PROJECT` 范围并传入当前项目编码；只有完成系统级权限判断后才能使用 `ALL`。A 负责数据范围隔离，不实现 B 的登录、鉴权或 HTTP 权限逻辑。
