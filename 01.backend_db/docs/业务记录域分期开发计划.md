# 智能建梁数字孪生平台业务记录域分期开发计划

- 文档状态：V8 已完成开发、独立测试、审计并冻结，V9 仍须单独设计和授权
- 计划版本：V6 至 V9
- 排除范围：设备时序测点

## 1. 目标

本计划依据《业务记录域暂行规则》，按低耦合、可审计和可独立回退的方式开发梁工序执行、质量检查、运输交接和设备告警记录。设备时序测点不在计划内。

四类记录不在一个版本内同时开发。每个版本只交付一个明确领域，完成测试与审计并冻结后再进入下一项，避免暂行规则在多个模块间形成连锁返工。

## 2. 版本安排

| 版本 | 领域 | 主要依赖 | 是否影响梁状态 |
|---|---|---|---|
| V6 | 梁工序执行记录 | `project`、`beam`、`process_definition`、`app_user` | 默认不影响 |
| V7 | 质量检查记录和检查项 | V6 可选关联、`beam`、`process_definition` | 默认不影响 |
| V8 | 运输交接记录 | `project`、`beam`、`app_user` | 默认不影响 |
| V9 | 设备告警记录 | `project`、可空 `beam`、`app_user` | 不影响 |

版本号为当前规划。V5 与 V6 因连续在同一未提交工作区完成，于 2026-09-15 作为同一个 6.0.0 基线冻结；不创建包含 V6 实现的虚假 V5 标签。V7 起恢复每个版本独立设计、开发、测试、审计和冻结。

## 3. 每个版本的固定交付流程

### 3.1 设计冻结

1. 从暂行规则中提取本版本字段、代码、约束和非目标。
2. 检查与现有模型、V3 审计、V4 工单和 V5 生命周期事件是否重复。
3. 明确 A/B 边界、项目隔离、作废规则、幂等规则和事务边界。
4. 形成独立设计决策文档，经确认后才开始编码。

### 3.2 数据层实现

1. 增加专用 ORM 模型，不改造成通用记录基类。
2. 生成一份可独立升级和降级的 Alembic 迁移。
3. 增加必要唯一约束、外键和最小组合索引。
4. CRUD 只承担明确的数据访问和锁定，不混入 B 的流程规则。

### 3.3 契约和 Service

1. 建立 Create、Read、Summary、Filter、SortField 和受控命令 DTO。
2. Service 负责引用解析、项目一致性、时间规则、幂等和异常转换。
3. 通过 `DatabaseServices` 增加独立只读或受控写入入口。
4. 对外只返回 DTO，不导出 ORM、CRUD、Session 或内部锁实现。

### 3.4 测试

每个版本至少覆盖：

- 正常创建、单条读取、筛选、分页和稳定排序；
- 项目隔离和跨项目引用拒绝；
- 重复业务编码和外部幂等重试；
- 时间边界和枚举非法值；
- 受控作废或状态动作的幂等与非法路径；
- 提交失败后的完整回滚；
- 迁移升级、降级、重新升级和 `alembic check`；
- V1 至当前版本的全量回归；
- wheel 构建及公开导入路径。

### 3.5 文档、审计和冻结

1. 更新 README、A-B 接入说明和数据字典。
2. 生成测试任务与审计任务交接文档。
3. 独立测试和独立只读审计不得直接修改业务代码。
4. 修复问题后重新全量测试和复审。
5. 确认迁移版本、包版本、提交范围和未完成事项后本地冻结；推送必须单独授权。

## 4. V6 梁工序执行记录实施计划

### 4.1 目标

提供一片梁在某道工序上的实际执行结果记录，为后续质量检查提供可选关联基础。V6 不建设生产计划、派工、流程图或状态机。

### 4.2 预计改动

- 新增 `beam_process_execution` 模型和迁移；
- 新增工序执行 DTO、CRUD 和 Service；
- 新增 `process_records` 公开接口；
- 实现项目/梁/工序一致性、时间校验、外部幂等和受控作废；
- 更新接口说明和 V6 数据字典。

### 4.3 关键测试

- 项目工序和通用工序均可用于项目梁；
- 停用工序不能创建新记录；
- 同一梁同一工序可多次执行；
- `SUCCESS` 必须有完成时间，结束时间不能早于开始时间；
- 幂等重试不会产生第二条记录；
- 作废后原始内容仍可查询；
- 创建或作废不会自动改变梁状态或写入重复生命周期事件。

### 4.4 完成条件

V6 独立迁移、定向测试、全量回归、数据字典、A-B 契约和审计全部通过，并且没有引入 B 的排程或权限实现。

## 5. V7 质量检查记录实施计划

### 5.1 目标

提供质量检查主记录和检查项明细，支持复检链和整体结果一致性。V7 不建设审批、签章、附件存储或自动放行。

### 5.2 预计改动

- 新增 `beam_quality_inspection` 和 `beam_quality_inspection_item`；
- 主记录与检查项在同一事务内创建；
- 新增 `quality_records` 公开接口；
- 支持可选关联工序和 V6 工序执行记录；
- 实现复检引用、结果汇总一致性和受控作废。

### 5.3 关键测试

- 检查项失败时主记录不能为通过；
- 复检只能引用同项目同一梁记录，且不能形成循环；
- 工序执行关联的项目、梁和工序必须一致；
- 主记录创建失败时检查项全部回滚；
- 作废主记录不物理删除检查项；
- 不合格记录不会自动修改梁状态。

### 5.4 完成条件

V7 能稳定保存检查结论和检查项，并允许未来增加专用质量模板，而不把检查明细塞入无约束 JSON。

## 6. V8 运输交接记录实施计划

### 6.1 目标

保存梁出场、途中转交和到场接收事实，为数字孪生平台展示运输里程碑提供数据。V8 不建设运输计划和实时轨迹。

### 6.2 预计改动

- 新增 `beam_transport_handover` 模型和迁移；
- 新增 `transport_records` 公开接口；
- 实现地点、车辆、承运单位及交接人员快照；
- 实现交接类型字段要求、幂等和受控作废。

### 6.3 关键测试

- 三种交接类型分别校验起点和终点字段；
- 接收和拒收均作为历史事实保留；
- 同一梁允许多次交接且稳定排序；
- 车辆和承运单位查询不跨项目；
- 不自动改变梁的运输或到场状态；
- 不出现经纬度或设备测点接口。

### 6.4 完成条件

V8 只表达交接事实，未扩展为调度、运单、车辆档案或轨迹系统。

## 7. V9 设备告警记录实施计划

### 7.1 目标

保存外部设备或系统已经产生的告警，并提供确认、恢复和关闭的受控状态变化。V9 不接入设备协议，也不根据测点计算告警。

### 7.2 预计改动

- 新增 `device_alarm` 模型和迁移；
- 暂以 `device_code` 字符串引用外部设备，不提前建设设备档案；
- 新增 `device_alarms` 公开接口；
- 实现设备侧幂等、项目隔离、可空梁关联和受控状态变化；
- 为未关闭告警和设备历史查询建立必要索引。

### 7.3 关键测试

- 同一外部告警重试只生成一条记录；
- 非法状态跳转被拒绝，重复动作幂等；
- 确认、恢复和关闭时间与状态一致；
- 关闭后不能重新打开；
- 梁关联必须与告警项目一致；
- 不保存设备原始报文、密钥或时序值。

### 7.4 完成条件

V9 只提供告警记录和受控状态，不实现采集、阈值判断、通知、工单、设备控制或时序存储。

## 8. 暂不开发内容

以下内容不因本计划自动进入开发范围：

- 设备时序测点和高频采集；
- 二维码、RFID 和一梁一码；
- 项目存量数据归属回填；
- 生产排程、派工和通用工作流；
- 质量审批、电子签章和文件存储；
- 运输任务、车辆实时轨迹和电子围栏；
- 设备档案、协议接入、告警计算和消息通知；
- B 的 HTTP、登录鉴权、页面和权限判断。

这些能力必须具有独立明确需求后另行设计，不在四类记录开发中顺带实现。

## 9. 风险控制

- 暂行规则可能变化，因此每个版本只增加一个领域，优先使用新增字段和独立迁移演进。
- 不在 V6 中预建 V7 至 V9 的抽象基类、通用 Service 或通用表。
- 不承诺未来业务变化完全不需要数据迁移；承诺保留旧数据含义并提供可审计迁移路径。
- 涉及梁状态联动、自动事件、审批或跨系统投递时必须重新设计事务，不能在现有 Service 中隐式增加副作用。
- 在真实数据量出现前只建立明确查询需要的索引，通过慢查询和使用场景决定后续索引。

## 10. 下一步

V8 运输交接记录已按独立单表、快照字段、项目隔离、幂等和受控作废契约完成开发，并通过独立测试与审计后冻结为 `backend-db-v8.0.0`。不自动进入 V9 告警记录开发；V9 仍需重新确认需求、设计并取得开发授权。
