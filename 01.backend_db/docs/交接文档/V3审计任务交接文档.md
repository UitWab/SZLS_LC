# 数据库模块 V3 审计任务交接文档

## 1. 审计目标

对 A 模块 V3 操作审计日志进行独立只读审查，重点识别数据完整性、敏感信息、迁移、接口耦合、查询性能、测试覆盖和 A/B 边界风险。

## 2. 必查内容

- `operation_audit_log` 是否只追加，公开层是否不存在更新、启停和删除；
- `project_id`、`actor_user_id` 可空及外键 `RESTRICT` 是否合理；
- `actor_name` 是否确实是快照而非鉴权依据；
- `action_code`、`result_code`、`source` 是否由B定义，A是否越界固化业务逻辑；
- `request_id` 是否仅追踪、非唯一且没有被误作幂等键；
- 审计Schema是否拒绝未声明字段，文档是否明确禁止敏感数据；
- 默认倒序及同值ID稳定排序是否正确；
- 组合索引是否与实际筛选一致且没有明显冗余；
- Service是否隔离ORM/Session并拥有明确事务；
- 迁移升级和降级是否与ORM一致；
- V1、V2公开契约是否发生不兼容变化；
- 是否出现FastAPI、JWT、消息、设备、告警、工单或UE5等越界实现。

## 3. 审计边界

审计任务只读，不修改代码、数据库、文档，不提交或推送。问题按P0至P3分级，给出文件位置、证据、影响和最小修复建议。没有发现问题时，应明确已审范围和仍未覆盖的外部限制。
