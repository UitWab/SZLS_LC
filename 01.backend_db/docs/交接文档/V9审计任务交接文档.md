# V9 审计任务交接文档

## 1. 审计目标

对 V9 未冻结工作区进行独立、只读审查，确认实现与业主“统一异常与待处理事项”需求一致，并评估数据完整性、项目隔离、幂等并发、状态流转、迁移、查询性能、异常契约和 A/B 边界。

## 2. 审计范围

- `abnormal_issue` 模型和 `a9d3e5f7b102` 迁移是否一致；
- Schema 是否覆盖长度、枚举、时间、操作人和筛选范围；
- CRUD 是否保持纯数据访问，不提交事务、不依赖 DTO；
- Service 是否承担引用校验、幂等、状态规则、事务和异常转换；
- Protocol、组合工厂和导出是否只暴露 DTO；
- 测试、设计、数据字典和 A-B 说明是否与实现一致。

## 3. 高风险检查

1. 是否错误地把 V9 限定为设备告警，遗漏进度、生产、质量、存梁、物流、安全和巡检异常。
2. 是否在 A 中加入异常计算、设备协议、通知、HTTP、权限或页面代码。
3. 项目是否真正必填，跨项目读取和操作是否泄漏数据存在性。
4. 可空梁是否强制与项目一致；设备编码是否错误引用不存在的设备表。
5. 幂等恢复是否在新事务中完成，停用项目是否仍允许既有记录重试。
6. 状态字段、时间、操作人和摘要是否可能形成不一致组合。
7. 行锁是否覆盖所有状态变化，并发动作是否会覆盖处理人或结论。
8. 关闭后是否存在重开、任意更新或物理删除路径。
9. 列表是否存在不稳定排序、跨项目扫描、不必要关系加载或缺失索引。
10. 是否泄漏 ORM、SQLAlchemy、PyMySQL、Session、SQL 或索引名称。
11. 是否隐式修改梁状态、生命周期事件或操作审计日志。
12. 是否为未来设备、工单或工作流提前增加高耦合抽象。

## 4. 边界

审计任务只读，不修改代码、文档或数据库，不提交、不打标签、不推送。设备时序测点、自动告警计算、通知、派工和 B 模块不属于 V9。

## 5. 结论格式

按 P0 至 P3 报告问题，提供文件和精确行号、触发条件、影响和最小修复建议。若无阻塞问题，明确说明是否可进入 V9 冻结流程，并列出实际执行的完整回归、并发、迁移和 wheel 证据。
