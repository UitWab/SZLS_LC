# V9 测试任务交接文档

## 1. 测试目标

独立验证 V9 统一异常事项记录的模型、迁移、DTO、CRUD、Service、公开接口、项目隔离、外部幂等、并发状态变化、查询和交付包。测试只验证 A 数据库模块，不增加或修改业务代码。

## 2. 基线

- 依赖冻结版本：`backend-db-v8.0.0`；
- V9 包版本：`9.0.0`；
- 目标迁移：`a9d3e5f7b102`；
- 目标数据库：MySQL 8.0；
- 测试库必须以 `_test` 结尾。

## 3. 重点文件

- `backend_db/models/abnormal_issue.py`；
- `backend_db/schemas/abnormal_issue.py`；
- `backend_db/crud/abnormal_issue.py`；
- `backend_db/services/abnormal_issue.py`；
- `backend_db/migrations/versions/a9d3e5f7b102_add_abnormal_issue.py`；
- `backend_db/tests/test_abnormal_issue.py`；
- `docs/V9异常事项记录设计草案.md`；
- `docs/V9异常事项记录数据字典.md`；
- `docs/A-B接口接入说明.md`。

## 4. 必测内容

1. 八类异常均可创建，项目必填，梁关联可空且必须同项目。
2. 设备编码仅为可空字符串，不依赖设备档案表。
3. `issue_code` 和 `source + external_record_id` 幂等规则正确。
4. 并发首次记录只产生一条数据，内容冲突返回公共异常。
5. 停用项目允许既有请求幂等重试，但拒绝新异常。
6. 状态只允许 `OPEN -> IN_PROGRESS -> RESOLVED -> CLOSED` 和 `OPEN -> RESOLVED`。
7. 未解决不能关闭，关闭后不能重开；相同动作重试幂等，不同内容不覆盖。
8. 并发状态动作由行锁串行，不出现丢失更新或底层数据库异常泄漏。
9. 项目、梁、设备、分类、类型、等级、状态、来源、时间和关键词筛选正确。
10. 同值排序追加 `id`，含总数和无总数分页均稳定。
11. 数据库检查约束、外键、唯一约束和五组组合索引与数据字典一致。
12. Service 返回 DTO，不返回 ORM、Session、SQL 或索引名。
13. 异常事项创建和状态变化不修改梁状态，不追加梁生命周期事件，不自动写操作审计。
14. 迁移在开发库和测试库执行升级、降级、重新升级后均与模型无差异。
15. wheel 为 `9.0.0`，包含 V9 代码和迁移，并可在隔离目录导入公开入口。
16. 完整回归 V1 至 V8，不接受仅运行 V9 定向测试。

## 5. 边界

不测试 HTTP、登录鉴权、页面、通知、异常计算、设备协议、阈值、测点时序、设备控制、派工或通用工作流。这些不属于 V9 A 模块实现。

## 6. 结果要求

报告应记录命令、通过数、失败数、数据库迁移版本、模型差异、并发轮次、数据残留、wheel 文件名和 SHA-256。发现问题时给出最小复现、严重级别和是否阻塞冻结；测试任务不修改代码、提交或推送。
