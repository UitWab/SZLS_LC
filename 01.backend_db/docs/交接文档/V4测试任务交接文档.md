# 数据库模块 V4 测试任务交接文档

## 1. 测试目标

独立验证 A 模块 V4 梁位工单的结构、数据契约、事务、并发边界和公开接口，并完整回归 V1 至 V3。测试任务只在名称以 `_test` 结尾的独立测试库写入数据，不修改开发库代码，不提交或推送。

## 2. 基线

- 目标包版本：`4.0.0`
- 目标迁移：`a4d7e9f2c105`
- 新表：`beam_position_work_order`
- 新公开入口：`create_database_services().position_work_orders`

## 3. 必测范围

1. 迁移从 `f8a2d4c6b901` 升级、降级和重新升级；升级后 `alembic check` 无差异。
2. 表的 14 个字段、主键、唯一工单编码、4 个外键和 2 个组合索引。
3. `PLACE`、`MOVE`、`RELEASE` 的完整创建、开始、完成流程。
4. 非法类型形状、非法状态流转、重复编码、跨项目访问和停用梁位。
5. 同一根梁只能存在一个未结束工单。
6. 创建工单不预占目标梁位。
7. 完成时原梁位变化、目标被占用等失败场景完整回滚。
8. 取消后允许创建新工单，完成或取消后不能再次流转。
9. 分页、无总数分页、筛选、关键词和稳定排序。
10. CRUD 只 flush 不 commit，且状态更新白名单不能修改业务字段。
11. 对外返回 DTO，不暴露 ORM；公开接口没有任意更新和删除方法。
12. 全量自动测试、源码编译、依赖检查和 Python 包构建。

## 4. 安全要求

测试前必须确认 `DB_NAME` 和 `TEST_DB_NAME` 均指向名称以 `_test` 结尾的数据库。不得对开发库或生产库执行 downgrade、清空、重建或测试数据写入。

## 5. 输出要求

报告应分别列出命令、实际输出、功能矩阵、迁移往返、最终数据库状态、残留数据检查和未覆盖风险。测试通过不代替代码审计。
